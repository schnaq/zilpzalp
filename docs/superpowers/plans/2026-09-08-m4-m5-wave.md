## Shared contracts

### Profile

```swift
public struct Profile: Codable, Sendable, Hashable, Identifiable {
    public var id: UUID
    public var name: String
    /// A `ZIcon` raw value from `Profile.avatarChoices` until Johanna's
    /// pictures arrive (#45); the field stays a string so pictures slot in.
    public var avatar: String
    public var totalStars: Int
    public var roundsPlayed: Int
    /// Bird ids from the manifests.
    public var collectedSpecies: Set<String>
    /// Seconds played per calendar day, keyed "YYYY-MM-DD" in the device's
    /// calendar; the store prunes everything older than seven days on write.
    public var playtime: [String: TimeInterval]
}
```

Rank is `RankLadder.rank(forStars: totalStars)`, always derived. The avatar
placeholder set is exactly `bird, egg, feather, leaf, star, sparkles, house,
lightbulb` (all vendored). Each avatar gets a fixed background colour from the
tokens so a child recognises the card by shape and colour.

### Files

Both under Application Support, both atomic (`Data.write(options: .atomic)`),
both with `schemaVersion` as the first key:

```
Profiles/profiles.json    { "schemaVersion": 1, "profiles": [Profile] }
Settings/parental.json    { "schemaVersion": 1, "callsEnabled": true,
                            "showNames": true, "dailyLimitMinutes": null }
```

Stores are actors in `ZilpZalpData`, constructed with the directory URL so
tests use a temporary directory. `dailyLimitMinutes == null` means no limit.

### Round result

Whatever #97 defines as the value the quiz hands to the round end (name and
fields as in `feat/quiz-screen`) is the contract. Task 23 consumes it, Task 26
records it. Nobody redefines it.

### Lock and gate

- `ParentsLock` (app target): `LAContext`, policy `.deviceOwnerAuthentication`.
- `ParentalGate` (app target): a view that asks an adult-level task — an
  arithmetic question with digits spelled out, new numbers on every attempt —
  and calls a closure on success. Used for every external link and as the
  lock's fallback. No answer is ever stored.

### Shell files and strings

`Route.swift`, `RootView.swift`, `AppModel.swift`, `HomeScreen.swift` are
shared surface. A task touches them only when the feature cannot work
otherwise and says so in the PR body. Credits and the ladder are local
destinations inside their parent screens. String Catalog keys are additive and
namespaced per task: `roundEnd.*`, `parents.*`, `gate.*`, `credits.*`,
`profile.*`, `collection.*`, `timeBudget.*`. Product strings stay German.

## Working mode — delta for the night

Everything from the previous plan holds: worktree per task, draft PR early,
`mise run check` seen green, `/simplify`, Sonnet review, `gh pr ready`, no
self-merge, English in the repo.

**Carrying.** Nobody merges before morning, so a task with a hard dependency
branches from `main`, merges the predecessor's branch into it, and opens its PR
against `main` with the first line "Carries #N until it merges; review only
…". After the predecessor is squash-merged, the branch merges `origin/main`,
re-runs check and pushes; identical content on both sides resolves cleanly (PR
#95 into #97 showed this today). This is not a stacked PR: base is always
`main`, and Christian merges in PR-number order, which is dependency order.
If he would rather not see carried diffs, the carried PRs wait as drafts.

**Concurrency.** At most four implementation agents at once; one Mac builds
for all of them.
