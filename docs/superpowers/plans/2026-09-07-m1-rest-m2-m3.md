## Decisions taken for this wave

These were agreed on 2026-09-07 and are binding for every task below.

1. **Three strands run in parallel:** A design system, B data, C game logic. None of them waits for another until the integration tasks at the end (C4 to C6).
2. **The base pack is bootstrapped now from the ten design photos** (`design/assets/photos/*.png`, 512×512, all CC BY 4.0, credited in `design/assets/photos/CREDITS.md`). A higher-resolution refetch through `tools/fetch-media` follows later and replaces the files without touching the schema. Issue #20 is split accordingly (new bootstrap issue, see B2).
3. **The bundled pack ships as a SwiftPM resource of `ZilpZalpData`**, not through the app's asset catalog as the spec says. Reason: `PackCatalog` then loads the real manifest and real files under `swift test` on the host, no simulator. This is a deliberate deviation from spec section 3 and is recorded there as part of task B2.
4. **Access work stays with humans:** #6 (Infisical machine identity, GitHub secrets) and #14 (Scaleway bucket public-read, write key). Tools that need them are built so they run and are tested locally without credentials (dry-run, local fixture directory) and get their first real run once the humans report the access exists.
5. **#21 species list:** an agent drafts a reasoned 60-species proposal as `docs/2026-09-07-deutschland-pack-species-proposal.md`; Christian and Johanna prune and extend. Media curation for that pack starts only after their decision.
6. **Branching:** one issue, one worktree, one `feat/…` branch from `main`, one pull request against `main`. No stacked PRs (lesson from M0). Humans merge. Agents rebase after conflicts.
7. **Licence identifiers** in manifests are the SPDX strings the gate already accepts: `CC0-1.0`, `CC-BY-4.0`, `CC-BY-SA-4.0`. The Swift `License` enum uses exactly these raw values.

## Working mode

- Implementation agents: Opus or Sonnet. One agent per task, spawned with the task section below plus the global constraints as its brief.
- Every PR states `Closes #N`, follows `.github/pull_request_template.md`, and shows the output of `mise run check` (green) in its description. For UI tasks add a rendered preview screenshot.
- Never self-merge. Never push to a branch you did not create for the task.
- After a PR merges, the controller checks the wave table below and starts the tasks that just became unblocked.

## Global constraints

- Code, comments, commits, PR text: English. Product strings: German, through `Localizable.xcstrings` only.
- Swift 6 strict concurrency, deployment target iOS 18, `mise run check` green.
- `ZilpZalpCore` imports Foundation at most, never SwiftUI, UIKit, `URLSession`, or file APIs. `ZilpZalpUI` contains no game logic. The app target is wiring only.
- `design/` and `screens/` are read-only reference.
- Touch targets never below 64 pt. `correct` is olive green, `retry` is sun yellow. Never red, never an X, never a blocked retry.
- No third-party dependency without a written check that it neither collects data nor opens network connections.
- Conventional Commits, imperative subject, 50 characters, body wrapped at 72.
- New logic in `ZilpZalpCore` and `ZilpZalpData` ships with Swift Testing tests in the same PR.

## Strand B — data and media (M2)

### B1 — Pack schema and Codable models (#13)

**Branch** `feat/pack-schema`. First task of the strand; B2 to B5 depend on it.

Define the manifest format once, in three places that must agree: the prose in `docs/medien-und-lizenzen.md` (already there), `tools/license_gate.py` (already enforces licence and attribution), and new Swift models in `ZilpZalpData`.

```swift
public struct Pack: Codable, Identifiable, Sendable {
    public let id: String            // "basis"
    public let title: String         // "Unsere zehn Vögel"
    public let schemaVersion: Int    // 1
    public let birds: [Bird]
}

public struct Bird: Codable, Identifiable, Sendable {
    public let id: String            // "amsel"
    public let name: String          // "Amsel"
    public let scientificName: String
    public let taxonID: Int          // iNaturalist taxon
    public let article: String       // "die"
    public let photo: MediaAsset
    public let call: MediaAsset?
    public var genus: String { scientificName.split(separator: " ").first.map(String.init) ?? scientificName }
}

public struct MediaAsset: Codable, Sendable {
    public let file: String          // relative to the manifest: "photos/amsel.png"
    public let sha256: String
    public let license: License      // CC0-1.0 | CC-BY-4.0 | CC-BY-SA-4.0
    public let attribution: String
    public let sourceURL: URL
    public let retrieved: String     // ISO date, informational
}
```

`bundled` and `downloadSize` from the spec sketch are **not** manifest fields: whether a pack is bundled is a property of where it was loaded from, and the download size belongs to `packs/index.json` (#50). Record this in the spec's data-model section.

Tests: decode the example manifest, reject a missing required field, reject an unknown licence string, `genus` for a two-word and a three-word (subspecies) name. Add `.gitkeep`-free `Tests/Fixtures/` with one minimal manifest.

### B4 — fetch-media: photos from iNaturalist (#15) and calls from xeno-canto (#16)

**Branches** `feat/fetch-media-photos`, `feat/fetch-media-calls`. Need B1 and, for the upload step, #14 from the humans. Both go into one package `tools/fetch_media/` with a PEP 723 script header or a `pyproject.toml` under `tools/` (decide in #15, #16 follows).

- Photos: `/v1/observations?taxon_id=<id>&photo_license=cc0,cc-by,cc-by-sa&quality_grade=research&rank=species`, never the taxon endpoint's `default_photo`. Rate limit 60 requests per minute. The tool lists candidates, a human picks by observation ID, the tool downloads the original, crops 1:1 to 1024×1024, writes the manifest entry with SHA-256.
- Calls: API v3 with `XENO_CANTO_API_KEY`, mandatory `lic:` filter (`PD`, `BY`, `BY-SA`; `CC0` returns nothing), one request per second, `type:song` first. The tool downloads candidates for listening; a human picks; the tool trims to a configurable length with ffmpeg and writes the entry.
- Both tools work without S3 credentials in `--local` mode (write into the pack directory only) and have unit tests against recorded JSON fixtures, no network in tests. Upload to S3 is a separate `--upload` step that reads `SCW_ACCESS_KEY`/`SCW_SECRET_KEY` from the environment (Infisical provides them, the tool never reads Infisical itself).
- Replace the `fetch-media` placeholder in `mise.toml`.

## Strand C — game logic and the playable shell (M3)

### C1 — Round engine (#22)

**Branch** `feat/round-engine`. `ZilpZalpCore`, pure. Independent of everything.

Input is a list of `RoundCandidate { id, genus, hasCall }` values defined in Core, so Core never imports `ZilpZalpData`. The app maps `Bird` to `RoundCandidate`.

- `Round.make(from:candidates, mode: .photoByName | .photoByCall, using: inout RandomNumberGenerator) -> Round?` with 10 questions of one target and three distractors each.
- Rules from #22 and the plan review: no target repeats while the pool allows it; when fewer than 10 eligible species exist repeats are allowed and pushed as late as possible; fewer than 4 eligible species returns `nil`. In `.photoByCall` only species with `hasCall` are targets; all species remain eligible as distractors.
- Distractor choice prefers a different genus; if the pool has too few genera, same-genus distractors are allowed rather than failing.
- Tests with a seeded generator: pool sizes 3, 4, 9, 10, 40; determinism for the same seed; the genus rule; the call rule.

### C2 — Scoring and rank ladder (#23)

**Branch** `feat/scoring-ranks`. `ZilpZalpCore`, pure. Independent.

- `Scoring.stars(firstTryCorrect: Int) -> Int`: 3 at 9 or more, 2 at 6 or more, else 1.
- `RankLadder` with the eight ranks and thresholds 0/25/60/100/150/220/300/400, `rank(forStars:)`, `next(after:)`, and progress toward the next rank as a fraction.
- Boundary tests at every threshold and at 5, 6, 8, 9, 10 answers.

### C3 — Speech output (#24)

**Branch** `feat/speech`. App target plus a tiny `Speech` module in the app (not in Core: it wraps `AVSpeechSynthesizer`). Independent of A and B, can start in wave 1.

- `AVAudioSession` category `.playback` configured once at app start so the mute switch does not silence game 1. Game 2 (#30) reuses this.
- `Speaker.speak(_ text: String)` with `de-DE`, cancels any running utterance first. The app builds "Wo ist die Amsel?" from `article` and `name`.
- Verify pronunciation of Zilpzalp, Hausrotschwanz, Eisvogel in the simulator and note the result in the PR. If a name needs a phonetic hint, add an optional `pronunciation` field to the schema in a follow-up, do not hack it into `name`.
